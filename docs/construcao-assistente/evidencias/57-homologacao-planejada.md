## Primeira fatia inerte

`scripts/assistant-smoke.mjs` aceita somente `plan --manifest FILE` e `preflight --manifest FILE`. Não oferece apply, seed, SQL, dispatch, chamada de modelo, URL/prompt arbitrário ou proxy de provedor. `plan` não usa rede. `preflight` faz nove GETs fixos da API Cloudflare da conta própria: settings/deployments da assistente, Archive e parser; schedules da assistente; metadados do D1 próprio e bucket ARTIFACTS próprio. Não lista contas/recursos, não consulta Elo/labs, não lê linhas D1, objetos R2, mensagens ou corpos dos serviços. Não chama RPC/DO/Container nem configura cron.

O token Cloudflare só entra por `CLOUDFLARE_API_TOKEN` do processo. Nenhum arquivo de credenciais é descoberto/lido, nenhum acesso da sessão é presumido e OAuth do Codex não é reutilizado. Transporte usa GET, redirects error, timeout 10s, JSON limitado a 256KiB e nenhum retry. Respostas/erros crus, valores dos bindings e token não são impressos; a saída contém checks, estados e hashes. Grafo exige bindings nominativos/tipados, sem duplicatas/capacidades extras. A versão precisa ser a do deployment atual integral, nunca uma versão antiga presente no histórico.

Manifest estrito contém schema=1, runId sintético estável, HEAD exato, installation do renderer #56, configHash igual ao review.json do renderer, versões UUID esperadas de assistant/archive/parser, phase staged ou shadow_fixture e budget com committedMicroUsd/includesUncertain/evidenceHash/additionalCeilingMicroUsd. Não admite credenciais ou destinos arbitrários. Soma financeira fornecida não ultrapassa US$10. Esse snapshot é referência a verificar no ledger vivo, não crédito novo/autorização de gasto. ConfigHash inclui os caminhos do checkout utilizado pelo renderer; render e smoke devem usar o mesmo checkout integrado.

A saída sempre mantém readiness pending e critérios funcionais pendentes. sourceHead atesta somente o checkout local; artifactMatch permanece unproven até comparação do bundle obtido por API com a saída do build. Os namespace_ids individuais dos cinco DOs precisam ser fixados no manifest real e verificados antes de execução: classname/binding correto não prova namespace. Leituras de metadados não formam snapshot atômico. Metadata_matches não comprova entrypoint RPC, migrações completas, imagem/buildFingerprint, execução de cron, ledger vivo ou canais. WhatsAppSend=false/CalendarWrite=false/modelCalls=false descrevem este CLI; zero efeito do produto exige evidência própria da jornada futura.
